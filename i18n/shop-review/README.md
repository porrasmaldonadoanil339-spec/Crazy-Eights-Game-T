# Shop translation review workflow

The shop currently ships ~700 items localized into 22 languages. Spanish (`es`),
English (`en`), and Portuguese (`pt`) are curated by hand. The other 19
languages were machine-translated and need a native-speaker pass.

This folder is the staging area for that review. Each language gets a single
CSV file that one reviewer owns end-to-end. Once a language is reviewed it is
imported back into `lib/storeItems.ts` in a single commit.

## Files

- `<lang>.csv` — one per language under review (e.g. `fr.csv`, `de.csv`, …).
  Generated by the export script, then edited by a reviewer, then merged back
  by the import script.
- `.review-state.json` — `{ ids: { <id>: { <lang>: <sha1-of-source_es> } } }`.
  Written by the import script, read by the check & export scripts to flag
  rows whose Spanish source has drifted since the last review. Commit it.
- This `README.md`.

CSV columns:

| column        | meaning                                                                |
| ------------- | ---------------------------------------------------------------------- |
| `id`          | shop item id (do not edit)                                             |
| `source_es`   | Spanish source — `name — description` (reference, do not edit)         |
| `source_en`   | English source — `name — description` (reference, do not edit)         |
| `name`        | localized name in this language — **edit this**                        |
| `description` | localized description in this language — **edit this**                 |
| `reviewed`    | set to `yes` (or `y` / `true` / `1`) once the row has been checked     |
| `stale`       | `yes` when `source_es` has changed since the row was last imported     |

The CSV is UTF-8 with a BOM so Excel and Google Sheets render Cyrillic, Arabic,
CJK, etc. correctly. Quoting follows RFC 4180; commas/quotes/newlines inside a
field are wrapped in double quotes.

## Workflow

### 1. Export

```bash
# Export all 19 non-curated languages (default)
npx tsx scripts/i18n-shop-export.ts

# Or pick specific ones
npx tsx scripts/i18n-shop-export.ts fr de it

# Include the curated es/en/pt as well (not normally needed)
npx tsx scripts/i18n-shop-export.ts --all
```

This regenerates `i18n/shop-review/<lang>.csv` from the current `ITEM_TL` block
in `lib/storeItems.ts`. Existing review state in those CSVs is **overwritten**,
so only re-export a language when you intend to start fresh (e.g. after the
shop catalogue grew and you want to pull in new ids).

### 2. Review

Hand the CSV to a native speaker. They:

1. Open it in Excel / Google Sheets / a CSV-aware editor.
2. Use `source_es` and `source_en` as context.
3. Edit `name` and `description` for any rows that need to change. Rows already
   correct can be left as-is — just mark them `reviewed = yes` to lock them in.
4. Set `reviewed` to `yes` for every row they have signed off on.
5. Save as UTF-8 CSV (keep the BOM). Send the file back.

Reviewers can leave half-finished CSVs in place; only `reviewed = yes` rows
will be imported.

### 3. Import

```bash
# Preview the diff without writing
npx tsx scripts/i18n-shop-import.ts --dry-run

# Import every CSV currently in i18n/shop-review/
npx tsx scripts/i18n-shop-import.ts

# Import only specific languages
npx tsx scripts/i18n-shop-import.ts fr de

# Emergency: import every row regardless of `reviewed` flag
npx tsx scripts/i18n-shop-import.ts --force-unreviewed
```

The import script:

1. Loads the live `ITEM_TL` from `lib/storeItems.ts`.
2. For each CSV row marked `reviewed`, replaces that `(id, lang)` entry.
3. Regenerates the entire `ITEM_TL` block between the
   `// ITEM_TL_START` and `// ITEM_TL_END` markers in `lib/storeItems.ts`.
4. Leaves all unrelated content in `storeItems.ts` untouched.

After import, run `npx tsc --noEmit` (or your usual type-check) and commit
`lib/storeItems.ts` together with the corresponding CSV(s) so the review
state is part of the git history.

### 4. Check coverage / staleness

```bash
# Print a per-language coverage table (exits 1 if any non-curated language
# has missing or stale rows; pass --no-fail to always exit 0)
npx tsx scripts/i18n-shop-check.ts

# Verbose: also list every offending id
npx tsx scripts/i18n-shop-check.ts --verbose

# Machine-readable
npx tsx scripts/i18n-shop-check.ts --json

# Just one or a few languages
npx tsx scripts/i18n-shop-check.ts fr de
```

The check script reads `lib/storeItems.ts` plus the `.review-state.json` hash
file written by the import script. For each language it prints:

- **total** — number of shop items in `ITEM_TL`
- **present** — items with a localized `name` or `description`
- **missing** — items with no entry at all in this language
- **stale** — items whose `source_es` has changed since the row was last
  imported via the review pipeline (only counted for ids that have already
  been reviewed at least once in this language)
- **coverage** — `present / total` as a percentage

Use this as a manual pre-release checklist gate: if `i18n-shop-check` fails,
either re-export the offending language, hand the CSV to a reviewer (the
`stale` column flags the rows that need re-checking), and re-import — or pass
`--no-fail` if you knowingly want to ship without it.

## Stale tracking — how it works

The import script writes `i18n/shop-review/.review-state.json`, mapping each
imported `(id, lang)` pair to a short SHA-1 of the Spanish source (`name` +
`description`) at the time of import. The check and export scripts compare
that recorded hash against the live `source_es` to decide whether a row is
"stale" (Spanish copy changed → translation may now be wrong). Commit
`.review-state.json` so the staleness signal is shared across machines.

## Conventions

- One language per pull request keeps reviewers and reviewers-of-reviewers
  sane. Don't merge a Korean review into the same commit as a Polish review.
- The 3 curated languages (`es`, `en`, `pt`) are still edited directly in
  `lib/storeItems.ts`. Don't run the importer for them unless you really want
  to round-trip the data through CSV.
- When you add new shop items: add them in `lib/storeItems.ts` with at least
  `es` (and ideally `en` / `pt`) entries, then re-run the export script. The
  next reviewer pass will pick up the new ids automatically — they appear with
  empty `name` / `description` columns.
- Don't hand-edit the `ITEM_TL` block for non-curated languages. Always go
  through this CSV pipeline so reviews are auditable.

## Where things live

- `lib/storeItems.ts` — `ITEM_TL` block (between the START/END markers) is the
  source of truth.
- `scripts/i18n-shop-export.ts` — emits CSVs from `ITEM_TL`.
- `scripts/i18n-shop-import.ts` — merges reviewed CSVs back into `ITEM_TL`.
- `lib/i18n.ts` — curated UI strings; reference these for tone/style when
  reviewing shop copy.
